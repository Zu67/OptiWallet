# OptiWallet

Credit card optimization tracker. Cards you pick from the catalog are the wallet, and the app stores that choice in this browser. The document title is "OptiWallet - Credit Card Dashboard". `package.json` names the package `optiwallet` at version `0.0.0`. `index.html` loads Tailwind from `https://cdn.tailwindcss.com` and maps packages to `aistudiocdn.com` at the same version ranges as `package.json`: React and React DOM `^19.2.0`, lucide-react `^0.555.0`, and recharts `^3.5.0`. The exact keys are `react`, `lucide-react`, and `recharts`. The prefix keys are `react/` and `react-dom/`. There is no exact `react-dom` key. The only import of that package is `react-dom/client` in `src/index.tsx`, which matches the prefix. The Tailwind config sets `slate.850` to `#151f32` and `slate.950` to `#020617`. No component uses `slate-850`.

The browser keys are `optiWallet_cards`, `optiWallet_balances`, `optiWallet_creditUsage`, and `theme`. A missing key starts the wallet as `[]`, the balances as `{}`, and the credit checks as `{}`. `JSON.parse` is called with no catch, so a stored value that is not JSON throws before the first screen. A value that is JSON but not an array still parses. `null` then throws `Cannot read properties of null (reading 'includes')`. An object, a number, or `true` throws because `includes` is not a function. A JSON string is used as the wallet, and a card is selected when its id is a substring of that string. The stored string `"capone_venture_x"` selects both `capone_venture` and `capone_venture_x`. The shorter id is also contained in a longer one for `boa_premium` and `boa_premium_elite`, `boa_alaska` and `boa_alaska_biz`, `capone_venture_x` and `capone_venture_x_biz`, `capone_venture` and both `capone_venture_one` and `capone_venture_x_biz`, `wyndham_earner` and `wyndham_earner_plus`, and `wf_autograph` and `wf_autograph_journey`. That throw happens during render, so the saved value is not rewritten. Balances and credit checks are not read on that first screen, so a saved `null` stays in those two keys. With at least one selected card, opening Points throws `Cannot read properties of null (reading '<id>')`, and the id is the first selected card in catalog order. Opening Credits throws the same way when a selected card has at least one credit. The property name is the first such card's id, a hyphen, and that card's first credit text. A number, `true`, an array, or a string does not throw on either screen: each lookup is undefined, so every balance box is empty and every credit is unchecked. The first balance edit, or the first credit toggle, replaces that value with an object. Spreading a string copies each character in as its own key, so a saved balance string `"100"` becomes an object with keys `"0"`, `"1"`, and `"2"` plus the card id. The theme starts dark when `theme` is exactly `dark`, or when `theme` is missing and `window.matchMedia('(prefers-color-scheme: dark)')` matches. That initializer does not add a change listener. Any other stored value starts light. The effect then writes `dark` or `light` back, so a first visit that prefers light stores `light`, and a later change in the system preference is ignored. A credit check is stored under `{cardId}-{credit text}`. Toggling the same card and the same credit text flips that one boolean.
